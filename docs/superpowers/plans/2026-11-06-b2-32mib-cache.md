# 32 MiB playback cache implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cache normal videos through 32 MiB without increasing CPU or I/O budgets.

**Architecture:** Read directly into one bounded initialized buffer, then return a
finished Core Cache stream instead of copying the complete buffer a second time.
Exclude incomplete cache writes using inferred completed length and a v2 key namespace.

**Tech Stack:** Existing Rust/Fastly 0.11.12, Core Cache, Viceroy/Python contracts.

**Spec:** docs/superpowers/specs/2026-11-06-b2-32mib-cache-design.md

## Global Constraints

- Maximum admitted body 33,554,432 bytes, plus one verification byte.
- Keep 25 ms admission CPU, 3 s buffering, 50 ms lookup, existing total deadline.
- No policy, erasure, provider selection, credential, dependency or worker changes.
- No partial HIT visibility; preserve bytes on short reads and timeout fallback.
- Local measurements cannot establish production CPU viability.

## Review Focus

- Short reads must continue without injecting initialized-but-unread zeroes.
- Failed cache insertion must preserve the complete origin response.
- Unfinished inserts must not satisfy HEAD or range HIT admission.
- Allocation failure and an oversized body must remain bounded.
- A successful response is not proof that a normal-sized body entered cache.
